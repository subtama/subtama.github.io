# PDCA自動改善ループ（Claude Codeが自走する仕組み）

「作って終わり」にせず、**データで勝ち記事を伸ばし、負け記事を直す**サイクルをClaude Codeに回させる設計。PCを開いておけば `/schedule` で定期実行できる。

## サイクル全体像
- **Plan**: keywords.md の実行キューから次に書くKWを決める
- **Do**: 記事生成 → build.py → deploy（公開）→ SNS拡散
- **Check**: アクセス/成果データを取り込み、勝ち負けを判定
- **Act**: 勝ち記事を強化（内部リンク集中・リライト）、負け記事を改善、新KWを追加

## データの入れ方（コスト0で始める）
最初は難しいAPI連携なしで運用可能。
1. **Google Search Console / アナリティクス**を公開後に設定（無料）
2. 週次で「検索パフォーマンス」CSVを `data/gsc.csv` に書き出す（早川さんが1クリックDL）
3. **ASPの成果レポート**CSVを `data/asp.csv` に置く
Claude Codeがこの2つを読み、下記の判定を自動で行う。

## Check（判定ルール）
- **伸びしろ記事**: 表示回数は多いが順位が11〜30位 → あと一押しでPV化。最優先リライト
- **勝ち記事**: クリック/成約が出ている → 関連記事を増やし内部リンクを集中（クラスター強化）
- **死に記事**: 90日経ってもインプレほぼ0 → タイトル/切り口を変える or 統合
- **成約ゼロ記事**: PVはあるが成約0 → CTAの位置・文言・訴求を改善

## Act（Claude Codeへの定期指示テンプレ）
`/schedule` に登録する指示（例・週1）：
> data/gsc.csv と data/asp.csv を読んで、docs/pdca.md の判定ルールで記事を仕分けして。
> ①伸びしろ記事を1本リライト ②勝ち記事に関連する新規KWを3つ keywords.md に追加し1本執筆
> ③成約ゼロ記事のCTAを改善。すべて build.py でビルドし、deploy.sh で公開。変更点を要約して報告して。

これで「分析→改善→公開」まで人手なしで一巡する。

## SNS拡散（初速を作る・参考動画のX×アフィリを反映）
SEOが育つまでの集客をSNSで補う。API不要、Claude Codeのブラウザ操作で運用。
- 新着/更新記事を **要約1〜2文＋記事URL** でX/Threadsへ投稿
- **文面は毎回AI生成で変える**、投稿間隔をあける（スパム判定回避）
- 1日数投稿から開始し、アカウントの信頼度を見て漸増
- 物販（Amazon/楽天）アフィリを絡めた"役立つ投稿"も並行（成約の裾野を広げる）
- 定期指示テンプレ：
> keywords.md の公開済み記事から1本選び、Threads向けに「役立つ豆知識＋記事誘導」の投稿文を3案作って。過去と被らない文面で。ブラウザでThreadsを開いて投稿して。

## 安全運用
- 料金など一次情報は月1で再確認（古い数字は成約を殺す）
- ブラウザ自動操作はサイト変更で止まることがある → 週次の定期実行時に動作確認
- 規約順守（ステマ表記・誇大表現回避）を毎回のチェック項目に含める

## スケジュール例（PC常時起動前提）
- 毎日: 記事1本生成＋公開＋SNS1投稿
- 週1: PDCA一巡（リライト・新KW・CTA改善）＋一次情報チェック
- 月1: ピラー記事の見直し・内部リンク再設計
